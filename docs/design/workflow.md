# worker の期限切れ

書きかけの文書が作業ツリーに残ると、以後は利用者の変更とみなされて保守の対象から外れる。そのため、worker の終了を確認できた期限切れでは、書きかけを戻す。

- **最初の起動**: 起動前の内容へ戻して失敗とする。同じ HEAD では hook から再起動せず（長い worker を繰り返さないため）、次の push か `run-now` で再試行する。
- **追い修正**: その起動の直前の内容へ戻し、追い修正を打ち切って保守後検査へ進む。完了した分の成果を活かすためで、期限切れは警告として残す。
- **利用者の変更の保護**: 終了確認の直後のハッシュと一致するパスだけを戻す。戻せないパスは、最初の起動なら記録して知らせ、追い修正なら commit せずに停止する。
- **終了を確認できないとき**（非 Windows を含む）: 子孫がまだ書く可能性があるので、何も戻さず停止する。
- **トレードオフ**: gitignore 済みの共有文書は Git で戻せないので、許可パスの内容をメモリに持つ。期限切れになった最初の起動の途中成果は捨てる。
