# セキュリティ（秘密値と管理画面の保護）

- CLI の出力（JSON・人が読む形式・doctor）に秘密値を入れない。パス・設定の要約・件数・定型の語だけにする。例外は `docs show` が返す利用者設定 `guidance` / `instructions` の本文。
- `claude auth status` は `maintenance::scrub_host_env` をかけ、終了コードと `authMethod` だけを見る。
- 管理画面は `127.0.0.1` だけに bind する。保護（Host → Origin / `Sec-Fetch-Site` → セッション Cookie → CSRF）は `guard` の 1 か所に集める。使い捨て鍵は一度だけ有効。セッション Cookie 名はポートを含める（`session_cookie_name`）。
- 常駐で「更新をインストール」が適用に進むときだけ、取得・検証の後で適用を依頼する直前に、64 桁の乱数の引き継ぎ鍵を発行し、JSON 応答（`handoff_key`）にだけ載せる。状態フォルダーの `ui-handoff.json` には鍵の SHA-256・ポート・発行と失効の時刻（10 分）だけを、適用の依頼の前に書く。適用に進まなかったとき・JSON でない送信のとき・書けないときは鍵もファイルも残さない。進行中の二重インストールは busy として断り、撤回（ファイルの削除）は自分が発行した鍵の分だけで、他のインストールの鍵は消さない。鍵・セッション・CSRF は保存・ログ・標準出力に出さない。新しい常駐は起動時に読んで必ず削除し（不正・期限切れ・ポート違い・発行が未来でも）、有効なときだけ `AppState` の引き継ぎ枠（`auth_key` とは別。トレイの鍵と互いに無効化しない）にハッシュを持つ。`/auth` は定数時間で照合して一度だけ受け付け、不一致では何も消費せず、移動先は許可リストの名前 `updated`（`/settings/app#updates`）。Cookie なしで通る経路は `/auth` のまま増やさない。
- 設定を変える POST は `handlers::apply_change` を通し、版の照合と `confirm::dangers(before, after)` による二段階確認を強制する（1 回目は書き込まず、nonce は 10 分で失効）。設定の書き込みと `run-now` は `ops` の関数だけを呼ぶ。
- GET は状態フォルダー・DB・ロックを作らない。秘密値・環境変数を表示しない（エンジン由来の自由文は `views::redact` を通す）。
- `GET /activity`（概要の「実行中」の自動更新）は `guard` を通る（Cookie 必須・no-store）が、無操作の時間を延ばさない（`guard` は method が GET でパスが `/activity` に完全一致するときだけ `touch` しない。ほかの判定は緩めない）。読み取り専用で、コマンド行・ヘッド・リモート・プロンプト・環境変数は出さない。
- 管理画面は 60 分無操作・Ctrl+C・画面の「終了」で終わる。`ui --tray`（Windows・macOS だけ）は常駐で、終了もセッションの失効もせず、アイコンの「開く」のたびに使い捨て鍵を発行し直す。
- 画面を足したら `tests/ui.rs` に保護・エスケープ・秘密値非出力の検査を足す。
