# 設定と保守の契約
- **設定の書き込みは `ops` / `config::update_in` だけ**（設定ロック・版（`Revision`）照合・変更前内容の退避（`config-history/`、50 件）・アトミック保存）。CLI・管理画面・自動移行が通る。`config::save` / `save_to` は `update_in` の外から呼ばない。変更関数は純粋・短時間にする（ロック保持中に呼ぶ）。
- **schema は 3 で保存する**。1/2/省略は旧形式で、読み込み時に変換する（同意あり・実効 push の登録だけそのまま。ほかは `paused` + `migrated_from`）。`migrated_from` の登録は `enable` でだけ再開し（resume・復元は拒否）、hook が旧形式を 1 回だけ書き換えて通知する。`consent` / `mode` を持つ schema 3 は不正。新項目は `skip_serializing_if` にする。既定の `documents` は従来 3 種。
- `enable` は保存前に `maintenance::baseline` で起点を記録し、有効化前の push を処理しない。`STATE_SCHEMA_VERSION` は 1 のまま、新しい状態は `CREATE TABLE IF NOT EXISTS` で足す（版を上げると旧版が何もしなくなる）。
- 契約の正本は同名のテスト（`tests/{maintenance,config,kinds,timing,changelog,ops,ui,cli,plugin_layout}.rs`）。`tests/compat_golden.rs` は従来 3 種のプロンプトと起動引数を `tests/golden/`（改行変換しない）で固定する。
- 状態と導入先は `src/paths.rs` が決める。テストは必ず `SCRIPTURA_DB` / `SCRIPTURA_CONFIG` か `SCRIPTURA_HOME`（CLI テストは加えて `CLAUDE_CONFIG_DIR` / `LOCALAPPDATA`）で隔離する。
- worker の事後検査: 全体比較は `restricted` のときだけで、無視ファイルは外す。許可パスの照合は `maintenance::is_allowed_path` に集約し、`normcase` 一致か、大文字小文字だけが違う綴りが同じ通常ファイルを指すとき（Unix は dev・inode 一致かつリンク数 1。判定不能は不一致）を一致とする。`normcase` は状態 DB のキーにも使うので変えない。`bypass` は commit 対象文書のハッシュ検査と分割先の新規エントリの検査（下の「分割先」）だけ。
- 文書の種類は組み込みの `AGENTS.md` / `DESIGN.md` / `README.md` / `CHANGELOG.md` と、`[kinds.<id>]` のカスタム種類（最大 20、固定パス・ASCII・文書拡張子のみ。id `new` は予約語）。**`CHANGELOG.md` とカスタム種類はオプトイン**（`documents` に挙げたときだけ動く）。組み込みの `paths` / `guidance` は拒否する。カスタムのパスは、組み込みの対象・`AGENTS.override.md`・`.gitignore`・機密パターン・`exclude`・種類間の重複を拒否する。
- **種類の検査は権限モードに関係なく Rust が行う**。上限・`required_headings`・AGENTS の 30,000 バイト未満の違反は、違反だけを直す再実行（最大 2 回。AGENTS の超過は階層の合計も対象で最大 3 回、縮まなければ打ち切る）のあと分類する。上限・見出し（ソフト）は警告つきで commit・push、AGENTS の 30,000 バイト・CHANGELOG のリリース済みエントリ不変（ハード）は worker の出力を破棄して完了にし位置を進める（`discard_outputs`）。階層の大きさは、commit に入る文書は作業ツリー・ほかは HEAD で数え、破棄したときは削るファイルとバイト数を通知する。
- **分割先（`split_dir`）**: `kinds::split_candidates` が許可パスへ入れる既存ファイルは、分割先直下の追跡済みで安全な名前の `*.md` だけ（`section-NN.md` も編集でき、件数に数える）。新規ファイル名は worker が内容に合わせて付ける（理由は DESIGN.md）。
  - 名前（`kinds::split_file_name_ok`）: 直下のみ、拡張子は小文字の `.md`、拡張子前は ASCII 小文字・数字・`-` の 3〜40 文字で、先頭は英字、`-` は末尾・連続不可。`agents` / `design` / `readme` / `changelog` と Windows の予約名は不可。`-` で区切った部分がすべて数字か仮置き語（`section`・`part`・`details`・`misc` など）の名前は不可。重複は大文字小文字を区別せず判定する。
  - 新規作成の許可（`kinds::split_grant`）: 分割先がリポジトリ内のリンクでない安全なパスで、無視対象でなく、直下の `.md` がすべて編集を許した追跡済みの未変更ファイルで（`git status` に加えて `git ls-files` の一覧でも確かめる）、件数が上限未満のときだけ。1 つでも欠ければ既存の編集のみ。件数は既存の分割先ファイルと今回の新規を合わせて 1 種類 20 件（`MAX_SPLIT_FILES`）まで。
  - 公開の状態の `split_dirs` に分割先・既存エントリ・許可の有無を記録し、`restricted` は許可があり残り件数がある分割先ごとに `Edit(./<dir>/*.md)` を足す。記録のない古い状態では新規作成を許さない。同じ HEAD の再試行では起動前に既存エントリと許可を今の状態から取り直し、条件を欠いた分割先は新規作成不可にする（失敗した worker の受理済みファイルが未追跡で残る場合を含む）。
  - 検査（`kinds::new_split_entries`）は、worker が正常終了・終了を確認できた期限切れ・失敗で終わるたびに、全体比較より前に行う。終了を確認できない期限切れと中断では行わない。受理した新規ファイルは許可パス・`before` と `after`（null）・その起動の checkpoint へ足してすぐ保存する（復元・破棄で消せる。直後に中断した記録は復旧でき、復旧は記録と違うファイルを消さない）。名前と件数が正しくても、Git の無視対象になる（または確かめられない）新規ファイルは拒否する。
  - 受理しない新規エントリは違反にする。許可した分割先では、フォルダー・リンク・`.md` 以外のファイル・名前の違反・件数超過のすべて、許可していない分割先では `.md`。1 つでもあれば権限モードに関係なく `worker_failed` にし、commit しない。ファイルは自動で消さない。違反の指紋は `worktree_snapshot_with` ではなく拒否パスの `path_fingerprint`（`split:` 印）で取る（無視対象や空のフォルダーは Git の状態の一覧に出ないため）。解除は内容の削除・変更で、`git add` しても解除されない。
  - 同じ HEAD では、違反のパスを消すか変えるまで再実行しない。新しい push では記録を作り直し、残った直下の `.md` は新規作成の停止要因になる。
  - 終了を確認できた期限切れと拒否が重なったときは、先に checkpoint の内容へ戻し（最初の起動は変更前、追い修正は直前の内容）、期限切れの通知に違反の文を続けて、commit せず `worker_failed` と `worker_timed_out` にする。このときの違反の文は再実行の一文を含まない `maint.split_name_invalid_no_retry`、追い修正の通知は「直前の内容を使う」を含まない `maint.fixup_timeout_reverted` にする。拒否したファイルを消しても同じ HEAD では自動で再実行しない（新しい push か run-now）。拒否のない期限切れと、`restricted` の範囲外違反だけの場合は従来どおり。
  - worker の起動前の一覧に無いファイルは worker が作ったものと区別できない。保守の実行中に利用者が許可済みの分割先へ正しい名前の `.md` を置くと worker 作と扱い、commit または削除することがあるので、実行中は分割先へファイルを置かない。
- **CHANGELOG の契約**: worker が編集してよいのは `Unreleased` 節だけで、リリース済み節は変えない。未リリース節の判定・版の節への移動・履歴の渡し方は [changelog-contract.md](changelog-contract.md)。
- **タイミングと worker の期限切れ**: 保守の起動・再試行は [workflow.md](workflow.md)、書きかけの復元は [troubleshooting.md](troubleshooting.md)。
- **保守履歴**: worker を起動した保守と失敗した回（hook・run-now）を、`poll_repository_with` が戻った後に 1 回 `maintenance_runs` へ書く（`runlog::record`。ベストエフォート）。起動も試行もしなかった回・`complete_recovery`・送信済み検知は記録しない。本文・差分は持たない。上限は DESIGN.md。
- `ops::restore` は、有効な登録が増える・有効に変わる版を拒否し、停止中の登録が増える場合は保存前に起点を記録する。
