# Admin UI (`scriptura ui`)

```powershell
scriptura ui [--port <n>] [--no-open] [--tray]
scriptura ui --autostart on|off
```

A browser screen for repositories, settings, history, and diagnostics, in 9 languages (footer selector cookie → `Accept-Language` → English). By default it ends on "Quit", Ctrl+C, or after 60 minutes idle. It needs cargo feature `ui` (default); without it the command refuses.

- **Listening**: only `127.0.0.1` (default port 7468; `--port 0` picks a free one; exits if in use).
- **Resident (`--tray`)**: tray icon on Windows, menu bar on macOS (Linux refuses). No idle exit or session expiry; each open issues a new one-time key (valid 5 minutes).
- **Resident at logon (Setup edition; on by default)**: turn off with `scriptura ui --autostart off` or the checkbox on the App screen (`tray_autostart` in `app-update.json`; a missing or unreadable value counts as on). It starts after the logon-time `update-apply`. Not available with the plugin-bundled or standalone `install` executable.
- **"App updates" panel (Setup edition)**: Settings › App (`/settings/app#updates`; the tray's "Check for updates" opens it and starts a check); shows the version, the auto-update and resident-at-logon checkboxes, "Check for updates" (ignores the 24-hour throttle, downloads nothing), and "Install update": it downloads, verifies the signer, and, if no other Scriptura process or run-now is active, asks the updater to apply it and ends the UI (otherwise retry later).
- **Protection**: the one-time key URL (`/auth?key=…`) is exchanged once for a session cookie (`HttpOnly; SameSite=Strict`; else 401). Host must be `127.0.0.1:<port>` or `localhost:<port>`; a POST needs same-origin plus a CSRF token. Secret values are never shown. Cookies are not isolated by port, so other local services of the same PC can receive it.
- **Conflicts**: a save is rejected with a reload request if the file changed elsewhere.
- **Confirmation screen**: enabling a repository, permission `bypass`, enrollment policy `all` / `remote-owner`, a custom kind's target path, removing a registration, `run-now`, and restoring history to a version containing these first list the changes and need one confirmation (valid 10 minutes).
- **Screens**: header: Overview (warnings, recent maintenance, repository status) / Repositories (register; the enrollment policy; a repository's detail puts its actions in the heading, internals in a collapsed section, and re-enable / remove at the bottom) / Maintenance history / Settings (`/settings/documents`). Settings tabs: Documents (one form for the settings shared by all documents: default targets, language, limits, shared instructions, exclusions; then the kinds list and `templates/`; a kind's screen shows the value actually in effect, and a value equal to the default is saved as unset) / Running maintenance (model and effort from lists; with `ANTHROPIC_API_KEY` set, "Refresh model list" fetches the newest models; the key is never stored or shown) / App (updates, resident at logon, version, settings file) / Settings history (diffs, restore) / Diagnostics. The old General screen (`/settings/general`) is gone and returns 404. `run-now` runs in the background.
- **Maintenance history**: each run that started the worker, and each attempt that failed before it could, is recorded in the state DB (`maintenance_runs`) and shown under "Maintenance history": trigger, kinds, result (committed / no changes / rejected / held / failed / outcome unknown), documents with line counts, commit, and reason; no contents or diffs. Up to 200 runs per repository and 2,000 overall are kept.
